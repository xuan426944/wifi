# 门店扫码 WiFi 广告收益平台 - 源码级 AI 开发总文档 V3.4

## 1. V3.4 定位
V3.4 是完整集成版源码级 AI 开发包。它在 V3.3 基础上正式加入 `29_Skills/UI_SKILL.md`，并明确 UI Skill 的使用时机，避免前期拖慢数据库、后端、收益、钱包、提现、风控等核心闭环开发。

项目主线不变：普通客户扫码进入 WiFi 首页，观看广告后连接 WiFi；授权商户查看收益、提现、排行榜、二维码；平台后台管理商户、门店、WiFi、广告、收益、钱包、提现、排行榜、风控、系统配置和第三方配置状态。

## 2. V3.4 核心变化

### 2.1 UI Skill 正式纳入开发包
新增 `29_Skills/UI_SKILL.md`，用于指导 PC 后台、小程序、商户入驻页、商家中心和原型页面开发。

### 2.2 UI Skill 使用时机明确
Phase 01-08 不强制使用 UI Skill，优先完成后端和业务闭环。Phase 09、Phase 10、Phase 13、Phase 14 必须使用 UI Skill。

### 2.3 新增 Phase 14
Phase 14 用于 UI Skill 验收与体验优化，集中补齐页面加载、空状态、错误状态、无权限状态、高危确认和合规文案。

### 2.4 保留 V3.3 能力
继续保留 UI 原型、商户自助入驻、广告合规提示、财务对账增强、测试用例增强、Mock + Adapter、部署后手动配置。

## 3. 产品主路径

### 3.1 普通客户路径
扫码进入 WiFi 首页 -> 点击一键连接 WiFi -> 用户主动观看广告 -> 广告完整观看 -> 后端发放 reward_token -> 小程序获取 WiFi 信息 -> 自动连接或手动连接。

普通客户不能看到商户收益、提现、钱包、商户二维码、商户排行榜管理、后台配置。

### 3.2 商家申请路径
普通用户/商家在 WiFi 首页右下角点击商家申请 -> 填写申请资料 -> 提交 -> 查看申请进度 -> 后台审核通过 -> 自动创建商户、门店、商户老板绑定 -> 进入商家中心。

WiFi 信息在申请时选填。审核通过后也可以由后台补充配置，不阻塞入驻。

### 3.3 授权商户路径
授权商户老板进入商家中心 -> 查看今日预估收益、昨日确认收益、本月收益、可提现金额、扫码数据、广告完成、连接成功 -> 查看排行榜 -> 申请提现 -> 查看提现记录和门店二维码。

### 3.4 平台后台路径
后台登录 -> 数据总览 -> 商户申请审核 -> 商户管理 -> 门店管理 -> WiFi 管理 -> 广告管理 -> 广告投放 -> 收益管理 -> 钱包管理 -> 提现管理 -> 财务对账 -> 排行榜配置 -> 风控中心 -> 系统配置 -> 第三方配置状态 -> 权限管理 -> 操作日志。

## 4. 开发原则

### 4.1 配置后置
微信 AppID、AppSecret、广告位、微信支付商户号、API v3 密钥、支付证书、商家转账权限、真实回调域名、真实 WiFi、真实广告结算全部在源码完成部署后手动配置。开发阶段必须使用 Mock + Adapter。

### 4.2 普通客户体验优先
WiFi 首页必须极简，主按钮必须突出。右下角商家申请入口不能影响客户连接 WiFi。

### 4.3 商户收益功能必须保留
商户端必须保留收益、可提现金额、提现、提现记录、排行榜、二维码和数据看板。

### 4.4 后台配置必须完整
后台必须能配置商户、门店、WiFi、分成比例、广告、提现规则、排行榜规则、风控规则、第三方参数状态。

### 4.5 UI Skill 不阻塞核心开发
UI Skill 只在前端和验收阶段强制使用。后端、数据库、钱包、提现、结算阶段不因为 UI 规则阻塞。

## 8. 验收重点
- 普通客户扫码后只看到简单 WiFi 连接路径。
- 商家申请入口存在但不干扰主流程。
- 授权商户能看到收益、提现、排行榜。
- 后台能完整配置商户、门店、WiFi、分成、广告、提现、排行榜、风控、第三方状态。
- Mock 模式能跑完整业务闭环。
- 所有敏感信息脱敏。
- 所有高危操作二次确认。
- 所有页面有加载、空、错误、无权限状态。

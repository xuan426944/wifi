# UI Skill 使用策略 V3.4

## 1. 为什么把 UI Skill 放进 V3.4
V3.3 已经补充 UI 原型，但 UI 规则仍是独立文件。V3.4 将 `29_Skills/UI_SKILL.md` 正式纳入源码级 AI 开发包，使 Codex 在前端阶段有统一页面规范，避免后台和小程序页面风格、字段、状态、权限表现不一致。

## 2. UI Skill 是否会拖慢开发
会增加少量前端细节工作，但不会拖慢核心后端开发，因为 V3.4 明确规定：

- Phase 01-08 不强制使用 UI Skill，以完成数据库、后端、Mock 闭环、收益、钱包、提现、风控为主。
- Phase 09 PC 后台页面开始使用 UI Skill。
- Phase 10 小程序页面开始使用 UI Skill。
- Phase 13 商户入驻、合规提示、财务对账增强使用 UI Skill。
- Phase 14 UI 验收与体验优化集中使用 UI Skill。

## 3. 不允许 Codex 因 UI 停止开发
Codex 不得因为没有 Figma、没有设计图、没有外部 UI 库而停止开发或反问。若没有 UI 资源，必须按以下优先级执行：

1. `29_Skills/UI_SKILL.md`
2. `23_UI原型与组件库/`
3. `05_小程序端/小程序页面字段级规格.md`
4. `06_PC后台/后台页面字段级规格.md`
5. `03_API接口/openapi.yaml`
6. `02_数据库/schema.sql`

## 4. UI 开发优先级
UI 开发时优先级必须是：

1. 功能可用
2. 权限正确
3. 字段完整
4. 状态完整
5. 文案合规
6. 视觉简洁一致
7. 最后再做美化

不得为了美化牺牲功能闭环。

## 5. 具体使用阶段

### Phase 09 - PC 后台页面
必须读取 UI Skill。重点开发：表格、筛选、表单、弹窗、详情抽屉、权限按钮、高危操作确认、空状态、错误状态。

### Phase 10 - 小程序页面
必须读取 UI Skill。重点开发：普通客户 WiFi 简洁路径、商家申请入口、商家中心、收益、提现、排行榜、手动连接兜底。

### Phase 13 - 商户自助入驻、合规、对账增强
必须读取 UI Skill。重点开发：商户申请表单、申请进度、后台审核页、广告提示、财务对账页。

### Phase 14 - UI 验收与体验优化
集中检查所有页面：字段、状态、权限、文案、操作日志、高危确认、响应式布局、Mock 数据展示。

## 6. 给 Codex 的调用提示词

```text
本阶段开始开发前端页面，请读取并遵守 29_Skills/UI_SKILL.md。
优先完成功能可用、字段完整、权限正确、状态完整。
视觉保持简洁，不做过度美化。
不得因为缺少 Figma 或真实配置反问。
```

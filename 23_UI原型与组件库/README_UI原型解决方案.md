# UI 原型解决方案 V3.4

## 目标
V3.2 已有字段级规格，但缺少真实 UI 原型。V3.4 不依赖外部 Figma 文件，直接在源码级开发包内提供三层原型资产，避免开发受阻：

1. **低保真文字原型**：小程序和 PC 后台每个页面的布局、区块、按钮、空状态、错误状态。
2. **可运行 HTML 原型**：`prototype/index.html`，Codex 可直接打开参考交互结构和页面层级。
3. **Codex UI 生成指令**：后台使用 Vue3 + Element Plus；小程序使用原生小程序或 uni-app 的卡片式轻量 UI。

## 是否可以调用 skill 仓库解决
可以，但不把它作为阻塞条件。Codex 开发时可根据项目可用能力选择：

- 有 UI / frontend / shadcn / Tailwind / Element Plus 相关 skill：优先使用这些 skill 生成页面骨架。
- 没有 UI skill：直接按本目录的低保真原型和字段级规格开发。
- 禁止因为没有 Figma、没有视觉稿、没有 UI skill 而停止开发或反问。

## 设计原则

### 普通客户小程序
- 扫码后第一眼只看见：门店名、WiFi 名、一键连接按钮。
- 商家申请入口固定右下角，尺寸小，不打扰客户连 WiFi。
- 普通客户不显示商家中心、收益、提现、排行榜入口。
- 广告失败、WiFi 未配置、连接失败都必须有简单提示和兜底。

### 授权商户小程序
- 仍可扫码连 WiFi。
- 右下角显示“商家中心”入口。
- 商家中心展示收益、提现、排行榜、门店二维码、数据概览。

### PC 后台
- 以“配置可落地”为核心：每个关键配置都有页面入口。
- 所有高危操作必须二次确认、权限校验、写操作日志。
- WiFi 密码、密钥、API v3 等敏感内容默认脱敏。

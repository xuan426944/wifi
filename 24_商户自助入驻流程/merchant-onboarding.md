# 商户自助入驻流程 V3.4

## 设计目标
普通客户扫码后只感受到简单 WiFi；真正的商家可以从 WiFi 首页右下角进入“商家申请”，自行授权登录并提交入驻申请。平台后台审核通过后，系统自动创建商户、门店、商户老板绑定关系，并可选择写入申请时提交的 WiFi 信息。

## 入口设计

### 小程序 WiFi 首页右下角
固定悬浮按钮：`商家申请`。

展示规则：
- 普通客户：显示“商家申请”，但不干扰 WiFi 主流程。
- 已提交申请用户：显示“申请进度”。
- 已授权商户老板：显示“商家中心”。
- 双身份用户：扫码仍默认进入 WiFi 首页，避免影响连 WiFi；商家入口在右下角。

## 申请流程

1. 用户扫码进入 WiFi 首页。
2. 点击右下角“商家申请”。
3. 后端通过 openid 判断是否已有商户绑定或待审核申请。
4. 没有申请则进入申请表单。
5. 用户填写申请人、手机号、门店信息、可选 WiFi 信息。
6. 用户勾选商户协议并提交。
7. 后台商户申请审核页出现待审核记录。
8. 超管或运营审核。
9. 审核通过后：
   - 创建 merchants。
   - 创建 stores。
   - 创建 merchant_owners，绑定申请人的 openid。
   - 如果申请里填写了 WiFi，则创建 store_wifi。
   - 创建 merchant_wallets 初始钱包。
   - 写 operation_logs。
10. 用户再次点击入口，进入商家中心。

## 申请字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| applicant_name | string | 是 | 申请人姓名 |
| applicant_phone | string | 是 | 手机号，可微信授权或手动填写 |
| store_name | string | 是 | 门店名称 |
| city | string | 是 | 城市 |
| district | string | 否 | 区县 |
| address | string | 是 | 门店地址 |
| industry | enum | 是 | 行业 |
| wifi_ssid | string | 否 | WiFi 名称，可后置配置 |
| wifi_password | string | 否 | WiFi 密码，可后置配置，加密保存 |
| remark | string | 否 | 备注 |
| agree_merchant_terms | boolean | 是 | 必须同意商户协议 |

## 后台审核规则

### 审核通过
必须二次确认。可配置项：
- 是否自动创建商户，默认是。
- 是否自动创建门店，默认是。
- 是否绑定申请人为商户老板，默认是。
- 是否写入申请 WiFi，默认是。
- 商户分成比例，默认读取全局。
- 门店分成比例，默认空。

### 审核驳回
必须填写驳回原因，可选择是否允许重新提交。

## 风控规则
- 同 openid 存在 active 商户绑定，不允许重复申请，只显示商家中心。
- 同 openid 存在 pending/reviewing 申请，不允许重复提交，只显示进度页。
- 同手机号 24 小时最多提交 3 次。
- 同门店名称 + 地址疑似重复时，后台提示可能重复，不自动拒绝。
- WiFi 密码不是必填，防止商户因不愿填写密码而无法申请。

## 不阻塞开发规则
商户入驻流程必须支持 mock 手机号、mock openid、mock 审核通过。不得因为没有真实微信手机号授权能力而停止开发。

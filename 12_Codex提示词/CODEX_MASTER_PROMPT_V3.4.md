# Codex Master Prompt V3.4

你是本项目的 AI 开发工程师。你的任务是根据仓库内 V3.4 源码级 AI 开发包，分阶段开发完整系统。

## 最高优先级业务规则
1. 不得偏离第一版业务主线：门店扫码 WiFi、观看广告、商户获得广告收益/佣金、商户看板、提现、排行榜、平台后台、风控、结算。
2. 普通客户登录/静默登录后，只能进入 WiFi 授权用户路径，不得看到商户收益、提现、商家排行榜管理、商户二维码管理等商家页面。
3. 只有通过后台绑定/邀请码绑定/扫码绑定并处于 active 状态的商户老板，才能看到商家中心页面。
4. 如果同一个 openid 既是普通客户又是商户老板，默认进入 WiFi 页面，但页面显示“商家中心”入口；不得影响客户快速连 WiFi。
5. 后台必须细分：超管、运营、财务、风控、客服、只读审计。不同角色按钮和接口权限不同。
6. 商户佣金、收益、可提现金额、提现记录、排行榜必须保留。
7. WiFi 连接体验必须简单：扫码后看到门店名称、WiFi 名称、一键连接按钮、广告提示、失败后复制密码和手动连接指引。

## 配置后置强制规则
源码开发阶段不得依赖真实微信配置、真实广告位、真实支付商户号、真实 WiFi、真实商户资料。必须先实现 Mock 模式和 Adapter/Provider 分层。

必须实现以下模式：
- AUTH_MODE=mock_wechat|wechat
- AD_MODE=mock|wechat|self|cpa|cps
- WIFI_MODE=mock|wechat|manual
- PAYMENT_MODE=mock|wechat
- TRANSFER_MODE=mock|wechat
- STORAGE_MODE=local|oss
- NOTIFY_MODE=mock|wechat

开发阶段默认全部 mock。上线后通过环境变量和后台配置切换真实配置。

## 禁止反问规则
除非出现不可自动解决的技术栈冲突，否则不要向用户反问。小缺口按文档默认值执行。

## 安全红线
1. 前端不能决定余额。
2. 后台不能直接改余额，只能通过 wallet_ledger 流水和人工调账审批。
3. 没有冻结不能发起打款。
4. 没有微信最终确认不能标记 paid。
5. 回调不验签不能处理，mock 模式也必须模拟验签。
6. 金额不一致必须进入人工复核。
7. 异常商户不能提现。
8. 商户不能查看其他商户敏感数据。
9. 预估收益不等于可提现收益。

## 开发流程
每次只执行一个 Phase。每个 Phase 必须：
1. 阅读该 Phase 任务书。
2. 读取相关规格文件。
3. 写代码。
4. 写测试。
5. 运行测试/构建。
6. 输出完成清单和未完成原因。
7. git commit。

# 门店扫码 WiFi 广告收益平台 - 源码级 AI 开发包 V3.4

## 最高目标
本包用于交给 Codex / Cursor / Claude Code / 其他 AI 编程工具按阶段自动开发。

对外产品定位：合规的门店扫码 WiFi 广告收益分成平台。
对内系统定位：平台可控的广告流量变现、商户佣金结算、WiFi 授权、提现、风控、排行榜和后台运营管理系统。

## 第一版主线不得偏离
1. 普通客户扫码进入小程序 WiFi 页面。
2. 普通客户只看到 WiFi 授权/广告/连接结果/手动连接兜底，不看到商家收益页面。
3. 授权商户老板登录后可以看到商家看板、收益、佣金、提现、排行榜、二维码、门店数据。
4. 平台后台管理商户、门店、WiFi、广告、收益、钱包、提现、排行榜、风控、系统配置、权限、操作日志。
5. 商户收益必须来自真实广告完成、广告结算、自营广告、CPA/CPS 或后台确认收入。
6. 禁止入门费、充值返利、投资回本、固定收益、多级团队分佣、下级缴费返佣。

## 所有真实配置后置
源码开发阶段不得因为缺少真实配置停止开发或提问。所有微信、小程序、广告、支付、商家转账、WiFi、商户资料、分成比例、提现规则、排行榜规则、风控规则、协议链接、广告素材均允许源码写完部署后通过后台/环境变量手动配置。

开发阶段默认使用 Mock + Adapter 完成闭环：
- AD_MODE=mock
- WIFI_MODE=mock
- PAYMENT_MODE=mock
- TRANSFER_MODE=mock
- AUTH_MODE=mock_wechat

## V3.4 强制补充规则
- UI 原型不再阻塞开发：优先参考 `23_UI原型与组件库/`；如有 UI skill 可调用，没有则按低保真原型直接开发。
- 小程序 WiFi 首页必须保持客户路径极简，主按钮是“一键连接 WiFi”，右下角才是“商家申请/商家中心”。
- 普通客户不能看到商户收益、提现、排行榜管理等页面；未授权访问必须 403 并回到 WiFi 首页。
- 商户自助申请必须可在没有真实微信手机号授权时使用 mock/manual 手机号开发。
- 广告合规提示、收益预估提示、提现门槛提示必须按 V3.4 文案落地。
- 财务对账必须支持 mock 对账差异，不因没有真实微信账单阻塞开发。


## V3.4 UI Skill 集成规则
- `29_Skills/UI_SKILL.md` 已正式纳入本项目。
- Phase 01-08 不强制使用 UI Skill，优先完成后端、数据库、Mock、收益、钱包、提现、风控闭环。
- Phase 09、Phase 10、Phase 13、Phase 14 必须读取并遵守 UI Skill。
- UI 开发优先级：功能可用 > 权限正确 > 字段完整 > 状态完整 > 文案合规 > 视觉简洁。
- 不得因为缺少 Figma、设计图、真实微信配置、真实 WiFi、广告位、支付商户号而反问或停止开发。
- 所有普通客户页面必须保持 WiFi 主流程极简；商家申请入口在右下角弱化展示。
- 所有授权商户页面必须清晰展示收益、提现、排行榜、二维码。
- 后台页面必须能配置商户、门店、WiFi、分成、广告、提现、排行榜、风控和第三方状态。
